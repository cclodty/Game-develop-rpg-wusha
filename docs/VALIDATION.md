測試日期：2026-10-23。版本環境：Godot 4.6.3 標準版、Dialogue Manager 3.10.4、Linux 雲端環境。

## 自動化規則與原生場景

`bash tests/run_tests.sh` 使用全新暫存使用者目錄，避免碰到任何玩家存檔。動畫套件沒有略過缺少素材的模式，必須驗證全部原圖與新增圖。每個測試程序必須完成明確的通過計數；Godot 即使回傳退出碼 0，只要出現 `SCRIPT ERROR` 或 `ERROR` 也視為失敗。

## 真正瀏覽器操作

以 Chromium／WebGL 2、1440×900 視窗對最終十二格動畫版本執行 `python3 tools/test_web.py --scope animation --record-video`，確認單執行緒版本不需要 cross-origin isolation。三種出身的非預設姓名、完整開場、角色建立、自由行走和各自存檔都經過真實滑鼠／鍵盤流程，合計通過 **6 組流程**。本輪瀏覽器回歸集中驗證動畫更新涉及的三種主角、實際移動、戰鬥及存檔恢復。

藥鋪出身的最終流程包括：讀完開場與斷點續讀 → 右／左／右行走 → 查看授課成本 → 完成授課取得劍氣 → 練習中實際 J／D／Space／Q 輸入 → 暫停、存檔、重新載入戰場 → 撤退而不領取獎勵。驛站與戲班出身也分別完成建立、專屬開場、移動及存檔核對。未變更的探索與選拔收束由本輪原生套件覆蓋；本次針對動畫的瀏覽器回歸沒有再次走完整個結局。

瀏覽器測試**沒有注入遊戲狀態**，只讀取 IndexedDB 來核對日期、目標、獎勵、武學和戰場；操作都由可見介面與按鍵完成。最終測試沒有 Godot 腳本或瀏覽器錯誤。最終匯出檔的 SHA-256、流程結果、錄影標記和 console 記錄位於 `artifacts/web/result.json`，畫面截圖同放於該目錄；README 的標題、望溪鎮與戰鬥截圖也已更新為此次匯出。

另以兩個字體的 cmap 核對全部遊戲程式和劇本文字，確認所有使用的非 ASCII 字元都有字形，並以實際畫面檢查輸入欄對比、中文字與選項。

## 逐格動畫與實際錄影

六個戰鬥角色各有待機、行走、出招、閃避、受擊、倒地六組動作，每組十二格；六名 NPC 各有十二格日常動作。合計 **42 組、504 個獨立繪製姿勢**。保留原本 252 格的 PNG 原始位元組，另外新增 252 格，依「原格 1 → 新格 1 → 原格 2 → 新格 2……」交錯播放。

十四張來源 PNG 的實際排列並非完全等距，採用量測的來源區域、透明留白與固定顯示範圍／落腳點。不同來源圖的站立尺寸以整張角色圖或整列 NPC 的單一等比係數校正；不依各格自身輪廓個別縮放，也不改寫來源 PNG 或靠扭曲立繪增加格數。新增考核教頭圖為 1536×1024，其餘來源為 1254×1254，均由來源中繼資料處理。

總動作時長維持不變：待機 1 秒、行走 0.6 秒、出招 0.32 秒、閃避 0.25 秒、受擊 0.24 秒、倒地 0.65 秒。待機／行走因此分別為 12／20 格每秒；普攻仍在 0.11 秒命中，對應零起算第 4 格。既有存檔的時間進度直接選取新畫格，不重設角色成長或戰場。

`tools/capture_animation.py` 在真正 Chromium 中按圖鑑的可見按鈕，通過 **5 組視覺／操作驗證**：暫停後角色區域像素不變、主角十二個行走姿勢各不相同、前後按鈕能在第 12／1 格之間循環、十二個角色都顯示新增的第二個實際姿勢，以及返回標題後沒有建立玩家存檔。比較區域排除文字與按鈕，另檢查畫格有可見人物，避免只因數字變動或缺圖而通過。圖鑑含兩排各六格的縮圖、朝向切換、半速、暫停與逐格控制。

`artifacts/animation-review/preview.mp4` 為 **40.32 秒、1440×900** 的實際瀏覽器錄影，展示主角六組動作、其餘戰鬥角色與六名 NPC。錄影器為 25 fps，因此另外透過圖鑑的真實半速按鈕播放出招／閃避，讓較快的新增姿勢有足夠時間顯示；畫面可見半速標籤，之後恢復原速。完整互動錄影保留為 `preview.webm`，影片僅剪輯、色彩範圍轉換與轉碼，未合成中間格。`docs/images/animation-preview.png` 為同次執行的原始截圖。

錄影需要 Playwright 的 ffmpeg recorder；MP4 另使用系統 ffmpeg。本次雲端由已安裝的系統 ffmpeg 提供 recorder，不需要遊戲玩家安裝這些測試工具。圖鑑結果、原始錄影時間標記與所測匯出檔 SHA-256 位於 `artifacts/animation-review/result.json`。

`tools/extract_review_clips.py` 另外從三種出身的原始遊玩錄影擷取實際右／左／右行走，以及藥鋪主角的實際戰鬥，產生 `herbalist-walking.mp4`、`courier-walking.mp4`、`performer-walking.mp4` 與 `herbalist-combat.mp4`。這些片段是遊戲中的按鍵操作，不是圖鑑演示或替換遊戲狀態；各片段的來源、時間區間與所測版本可由 `artifacts/animation-review/clips.json` 核對。

## 可重建交付

`tools/export_web.sh` 比對 Godot 官方 4.6.3 匯出模板 SHA-512，重用既有快取，產出 Compatibility renderer、單執行緒的 Web 遊戲。匯出附帶 Godot、Dialogue Manager 與 Noto 字體授權。

`tools/package_release.py` 產出獨立的原始碼與可玩 ZIP，附 SHA-256，並拒絕達到 100 MiB 的封存檔。原始碼排除 `.godot`、匯出目錄、測試產物及遊戲存檔；可玩包包含 Windows 內建 PowerShell 啟動器和 Python 本機伺服器。固定遊玩網址使用 8070，舊原型的 8060 與舊存檔位置保留。本次十二格更新沿用《江湖未遠》既有的版本 1 存檔格式與相同動作時間，不需要遷移或重開存檔。

Windows 啟動伺服器另以 Linux 上的 portable PowerShell 執行未修改副本，搭配暫存 Web 檔案完成 **36 項檢查**：完整 2 MiB WASM 位元組與 MIME、PCK／JavaScript MIME、HEAD、只監聽 loopback、13 種無效路徑、404／405／431、閒置／不完整連線恢復、六個並行完整下載、埠占用與缺檔時的可理解錯誤。CMD 檔為 ASCII／CRLF 且正確引用含空格路徑。這是啟動器實作的執行測試，並不等同真正 Windows 或 Windows PowerShell 5.1 實機驗收。

## 尚需真人驗證

- 30–60 分鐘是設計目標，沒有以真人從開場到結束的計時結果宣稱已達成。
- 可讀性、第一次遭遇的反應時間、兩條養成路線的樂趣與平衡仍需玩家回饋。
- 本輪沒有在真正 Windows 桌面、Safari、手機或手把上完成實機驗收。瀏覽器腳本以逐鍵方式輸入 ASCII 自訂名稱；真正中文輸入法尚未實機驗證，不能以 Playwright 的 DOM `insert_text()` 代替。
- 動畫目前為右前方視角，向左使用水平鏡像；並非四向或八向獨立繪製。每組十二格，動作銜接與表演細節仍可持續打磨。
