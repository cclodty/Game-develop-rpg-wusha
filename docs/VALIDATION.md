# 首篇驗證記錄

測試日期：2026-10-23。版本環境：Godot 4.6.3 標準版、Dialogue Manager 3.10.4、Linux 雲端環境。

## 自動化規則與原生場景

`bash tests/run_tests.sh` 使用全新暫存使用者目錄，避免碰到任何玩家存檔。每個測試程序必須完成明確的通過計數；Godot 即使回傳退出碼 0，只要出現 `SCRIPT ERROR` 或 `ERROR` 也視為失敗。

| `test_arena.gd` | 62 | 實際時間推進的普攻／劍氣／突進、敵人預警、閃避、身力、回復藥、投射物、敵波、頭目破綻、暫停和 JSON 戰場恢復 |

合計 **813 項檢查通過**。最終 UI 程序沒有引擎錯誤或退出資源洩漏。

UI 測試直接按遊戲場景中的按鈕、傳入鍵盤事件，並讓真正敵人攻擊至戰敗來驗證重試。九種「出身 × 去向」的結局呈現使用明示的已達成準備條件資料；能否在 21 時段內達成條件，由規則套件另行驗證。中斷恢復測試也使用儲存斷點資料，覆蓋最後一項城鎮目標、危險標記、探索勝利尚待結算及僅剩備份存檔的狀態。

## 真正瀏覽器操作

以 Chromium／WebGL 2、1440×900 視窗執行 `tools/test_web.py`，確認單執行緒版本不需要 cross-origin isolation。三種出身的完整開場、角色建立、自由行走和各自存檔都經過真實滑鼠／鍵盤流程。首次完整瀏覽器檢查通過 7 組流程；最後的字形修正與場景定稿後，再對最終匯出執行 `--origins herbalist`，完成包含結局的 6 組流程。

最終流程包括：讀完開場與斷點續讀 → 走動 → 查看授課成本 → 完成授課取得劍氣 → 練習中實際 J／D／Space／Q 輸入 → 暫停、存檔、重新載入戰場 → 撤退而不領取獎勵 → 由地圖安排溪谷外出 → 親自走到線索、存讀後繼續下一線索 → 確認略過剩餘準備 → 第八日選拔 → 拱手認輸 → 選擇留鎮並讀完收束。

瀏覽器測試**沒有注入遊戲狀態**，只讀取 IndexedDB 來核對日期、目標、獎勵、武學和戰場；操作都由可見介面與按鍵完成。兩次完整完成的測試均沒有 Godot 腳本或瀏覽器錯誤。最終匯出檔的 SHA-256、流程結果和 console 記錄位於 `artifacts/web/result.json`，畫面截圖同放於該目錄；README 的標題與望溪鎮截圖也來自最終匯出。

另以兩個字體的 cmap 核對全部遊戲程式和劇本文字，確認所有使用的非 ASCII 字元都有字形，並以實際畫面檢查輸入欄對比、中文字與選項。

## 可重建交付

`tools/export_web.sh` 比對 Godot 官方 4.6.3 匯出模板 SHA-512，重用既有快取，產出 Compatibility renderer、單執行緒的 Web 遊戲。匯出附帶 Godot、Dialogue Manager 與 Noto 字體授權。

`tools/package_release.py` 產出獨立的原始碼與可玩 ZIP，附 SHA-256。原始碼排除 `.godot`、匯出目錄、測試產物及遊戲存檔；可玩包包含 Windows 內建 PowerShell 啟動器和 Python 本機伺服器。固定遊玩網址使用 8070，舊原型的 8060 與舊存檔位置保留。

Windows 啟動伺服器另以 Linux 上的 portable PowerShell 執行未修改副本，搭配暫存 Web 檔案完成 **36 項檢查**：完整 2 MiB WASM 位元組與 MIME、PCK／JavaScript MIME、HEAD、只監聽 loopback、13 種無效路徑、404／405／431、閒置／不完整連線恢復、六個並行完整下載、埠占用與缺檔時的可理解錯誤。CMD 檔為 ASCII／CRLF 且正確引用含空格路徑。這是啟動器實作的執行測試，並不等同真正 Windows 或 Windows PowerShell 5.1 實機驗收。
